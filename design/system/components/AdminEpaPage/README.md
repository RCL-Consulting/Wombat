# AdminEpaPage

An EPA's page in the catalogue (`/admin/epas/new`, `/admin/epas/{Id}`, `Pages/Admin/Epas/EpaEdit.razor`; its words `EpaWords.cs`, the fields' refusals `EpaFieldMessages` in `CreateEpa.cs`; the read `GetEpaPageQuery`, `EpaPageDto`; the commands `CreateEpaCommand`, `UpdateEpaCommand`, `DeactivateEpaCommand`; refusals under fields through `Components/Shared/FieldRefusal.cs` and `FieldRefusalException`; the result token `CatalogueLinks`): **one EPA as the catalogue keeps it: a form where the caller may change it, a record where they may not.** Not the trainee's EPA page (EpaPage, flow 05), which reads a registrar's standing on an EPA. Flow 15 (T392, 2026-11-02, c931d56f; boards R3-C08, C12, C18a, C18b and R2-C04 to C07, C10, C11, C13, C14, C19; Q2, Q11, Q12, Q19, F1, F4, F9, M5, S4, S8, S11, S19, T7; build review P4, N4, N5) rebuilt it. Until then it was "Edit EPA" for every EPA, a national one too (whose save `UpdateEpa` refused, T291), offered Back to EPAs, put a refusal at the top in a validation summary, printed an exception's text (T272, T329), and said "every institution that uses it" when deactivating an institution's own EPA.

## Who reads it

Administrator, College admin and Institutional admin (`NationalCatalogueAccess`), each reading by the EPA list's rule (Epas): an id outside it, and an unknown one, are **EPA unavailable** alike (Q2, Q19), so the Demo College's EPA-001 typed by Kgosi Kgari's admin is never a form. Reached from a row's link or Edit on EPAs, or Create EPA; EPAs is lit, and the trail is Home › EPAs › the EPA's code.

- **EPA unavailable** (R2-C11): h1 and crumb "EPA unavailable", the empty card "This EPA does not exist, or you cannot open it." and **Go to EPAs** (primary); no id shown.

## Refusals under their field (F4, F9; DESIGN.md § Form system)

Save checks the required fields first, in the form's order, each under its own field ("Choose a sub-speciality.", "Enter a code.", "A code is at most 64 characters.", "Enter a title.", "A title is at most 200 characters.", the lengths of Description and Required knowledge and skills; `EpaFieldMessages`, so the page and the validators say the same, never a property's name, T324). A command's own refusal of one field arrives as a `FieldRefusalException` or a validator failure about one property (`FieldRefusal.Of`) and lands the same way: a duplicate code, "An EPA with the same code already exists for this sub-speciality." under Code (T272); an own EPA created in, or moved by a save into, a discipline its institution has not actively adopted, "Your institution has not adopted Paediatrics / Paediatrics, so an EPA cannot be added to it." under Sub-speciality ("Kgosi Kgari Teaching Hospital has not adopted …" to an Administrator moving one; a save that keeps the sub-speciality is not refused; F9, Q12). Each is a `div.validation-message[role="alert"]` with the id `‹input›-refusal`, named first in the control's `aria-describedby` (then its help), the control `aria-invalid` (by the form's own message store, so `InputBase` sets it), the first refused field focused, what was typed kept. No `ValidationSummary`, no `RefusalSummary`. Any other failure is fixed words in the result region, focused, the cause logged (T329): "The EPA could not be saved. Nothing has changed. Try again, or come back in a few minutes." (R2-C06).

## Deactivate (Q11, S8, S11; T158, T196, T312)

Deactivate…, and Save with Active unticked on an EPA stored active, open **one** `ConfirmDialog` (action mode, so it opens on Cancel), named for the EPA: "Deactivate PAED-012?" over "It can no longer be chosen for a new activity, and it stops being a target on running programmes' progress pages and dashboards, for every institution that has adopted it. A programme that has ended keeps it on its record, marked no longer in use. The progress it has earned is kept. An activity completed against it while it is inactive counts towards nothing until it is reactivated. You can reactivate it on this page." ("… for Kgosi Kgari Teaching Hospital's trainees." for an own EPA); **Deactivate**, the filled danger button. Cancel or Escape returns the focus to its trigger; a Save it interrupted leaves Active unticked, unsaved, and Save asks again. Confirmed from Save, it saves every edit with the deactivation.

## Results (T234, F1, M5)

One result at a time, in the `ActionResult` at the form's top, focused once the action has answered and any dialog has closed: "EPA saved.", "EPA saved and deactivated.", "EPA deactivated." (Active unticked, Deactivate… gone), or a reactivation's count, "EPA reactivated. 1 activity completed against it while it was inactive now counts towards progress." ("… No activity was completed against it while it was inactive, so no progress changed." for none; T196, D48). **A create leaves for its new EPA's page** by `?created` (`CatalogueLinks.EpaCreated`): that page writes "EPA saved." itself, focuses it, then replaces its address without the token, so a reload says nothing. A failed deactivation: "The EPA could not be deactivated. Nothing has changed. Try again, or come back in a few minutes.", focused once the dialog has closed (build review P4).

## States

- **Loading**: h1 "EPA", `p.loading-line[role="status"]` "Loading this EPA." over a skeleton card (S19, R3-C18a).
- **Load failed**: h1 "EPA", "Could not load this EPA. Nothing has changed. Try again, or come back in a few minutes." with Try again (StatePanel, `refresh-cw`; R3-C18b), which focuses the h1 once it reads. A read that throws is not Unavailable.

## Narrow widths

Below 641px `.user-page`'s rules hold: every control 44px, the form's actions stacked with Save on top (Cancel first in the tab order), the dialog's buttons stacked with Deactivate on top. **Status's Active row is a 44px target** (`.user-page.epa-page .form-check`, its box 20px, its label the row; round-3-check decision 2), as the item page's checkbox rows are. Measured on the replay's states at 390: nothing sideways.
