# T312 review: correctness, data and concurrency (branch t312, 4b65b0f3)

Severity: M must fix, S should fix, N nit. No code edited.

## Findings

**B1 (S) Removing a curriculum item after the end leaves a ghost card on the closed record.**
`ProgrammeItems.ReadAsync` (src/Wombat.Application/Features/Curricula/ProgrammeItems.cs, ended branch) builds an ended item from the frozen JSON and checks only that the EPA exists, never that `CurriculumItemId` still exists. `RemoveCurriculumItemCommandHandler` (ManageCurriculumItems.cs:327-356) deletes the item, and `CurriculumItemProgress` cascades (CurriculumItemProgressConfiguration.cs:46). A graduate's closed years then read "0 of N, short" on an item whose rows were deleted: the same class of defect T312 closes (a catalogue edit after the end rewrites the record), reached through a different edit. Fix: refuse removing an item that appears in any ended profile's frozen list (the progress rows are lost anyway), or at least test and document it.

**B2 (S) A scale a frozen item pinned can be deleted or re-pinned out from under the record.**
`EndedCurriculumItem.ScaleId` is frozen, but `EntrustmentScaleReferences` / `DeleteEntrustmentScaleCommandHandler` count only live `CurriculumItems.ScaleId`. If an item is re-pinned after the end, the old scale is unreferenced and deletable, and `EntrustmentRungLabels.LoadAsync` / the standing cannot label the frozen minimum. Fix: include frozen ScaleIds in the references check, or document and test the degraded rendering.

**B3 (S) The trajectory chart on an ended record still reads live targets.**
GetEpaTrajectoryForTraineeQuery.cs:753-760 loads `ScaleId`, `MinimumLevelOrder`, `MinimumLevelByStageJson` from the live `CurriculumItems` for the profile (and picks up a local item added after the end); `MinimumSteps` / `AgainstMinimumThen` then draw the dashed minimum and judge each rating against it. A minimum edited after the end rewrites the closed chart, and the PDF trajectory (PortfolioPdfService reuses this handler). The task lists four readers, but the stated rule is "every reader of an ended record", and the card beside the chart now disagrees with the chart. Fix: when `ProgrammeItems.ReadsEndedList(profile)`, build `pins` from the frozen list (all needed fields are in `EndedCurriculumItem`); keep "a paused EPA still charts" by not filtering on EPA state.

**B4 (S) EpaCountLines still reads live, in-force items for an ended profile.**
EpaCountLines.cs (~L85-100) uses `.InForce()` plus live `RequiredCount` / `QuotaPeriod` with the preferred profile, which may be ended (its projection carries `EndedOn`). Used by GetActivityCountLineQuery and DecidedOnYours for the completed card. For a graduate an EPA paused after the end gets no count line, and a changed RequiredCount changes the count. Fix: for an ended profile read `ProgrammeItems.ReadAsync(...)` and key by EpaId.

**B5 (S) STARs issued after the last day are hidden from an ended record, including on the committee page.**
EntrustmentStandingReader.DecisionsInForce applies `IssuedOn <= lastDay` for every ended profile regardless of caller. Nothing stops a sitting (ReviewDetail.razor:344, ratify) issuing a STAR to an ended trainee after her last day (no EndedOn / IsActive guard in RatifyCommitteeDecision); that STAR never appears in the standing the panel is looking at. Probably rare, but it is an unstated product decision. Fix: refuse STARs after the end, or let the committee path read live; confirm with the operator and record it in the task.
Checked and correct: expiry is inclusive (`ExpiresOn >= lastDay` matches `MarkExpired` refusing while `ExpiresOn >= today`); revoked uses `RevokedOn >= EndOfLastDay` on the `DateTime?` that `Revoke` always sets; superseded checks the successor's `IssuedOn <= lastDay`. A Superseded row with null `SupersededByDecisionId` is kept (transient only).

**B6 (N) Pause during the last day.** `moment = min(EndOf(lastDay), now)` means "in force at the close of the last day". An EPA paused at 09:00 on the last day is left off though in force most of that day. Consistent with "paused before the end left out" and with the migration; say "at the close of the last day" in DESIGN.

**B7 (N) PDF "deactivated" lookup (PortfolioPdfService.cs:478-485).** For an ended profile, an EPA paused before the end and reactivated since is neither targeted nor `NotInForce`, so it prints as an untargeted EPA with evidence and not with the paused note. Harmless; the comment at L469-472 should say so.

**B8 (N) ErasureExecutor (~L327-338).** Reads the list for an active profile before `Erase`, records after; correct, and `RecordEndedCurriculum` guards a double record. The erasure ends the profile without `ITraineeCreditLock.HoldForEndAsync` (pre-existing), so the list is read outside the end hold on that path. Benign (a concurrent EPA pause has `DeactivatedOn` >= the read moment), worth one sentence in the comment.

## Held (checked, correct)

- **Freeze in the same save, under the hold.** Complete and Deactivate take `HoldForEndAsync` before the profile read, call `ReadEndedWithAsync` before `profile.Complete/Deactivate` (a refused end writes none), then `RecordEndedCurriculum`, then `ProgrammeEndCredit.SaveAsync` and `hold.CommitAsync`. The read is `AsNoTracking`.
- **Rollback.** ProgrammeEndCredit.cs:111-119 does `CurrentValues.SetValues(OriginalValues)` and sets `Unchanged`; `EndedCurriculumJson` is a mapped scalar, so it resets with the end.
- **Semantics.** `InForceAt(moment)` is `IsActive || (DeactivatedOn != null && moment < DeactivatedOn)`, the rule credit uses (D48). `ProgrammeCalendar.EndOf` is next-day midnight minus the +2h offset, UTC kind. The local-items rule is the shared `OfCurriculum`; `IsLocal` is frozen. A concurrent EPA deactivation is benign: its `DeactivatedOn` is >= the read moment, so either order agrees. Reactivated-in-the-gap and item-added-in-the-gap limits are documented.
- **Running trainee unchanged.** The non-ended `ReadAsync` branch is `OfCurriculum(...).InForce()` ordered by Epa.Code, the same query as before; `ReadItemAsync` live branch and the `Paused` list are unchanged for running profiles; `OnListOf` is unchanged in effect and still serves GetMsfProgrammeCoverage. CurriculumCoverage, GetCommitteeRouting, StarCurriculum, ActivityReferenceDataService, ListActivityTypes are running-trainee or target paths and rightly keep `InForce()`.
- **Readers switched:** TraineeQuotaProgressReader (ReadForProfileAsync, ReadItemAsync, EpasWithAPageAsync), EntrustmentStandingReader (the exit rule counts the frozen items), GetMsfCoverageForTrainee (profile is now the whole untracked entity; `EndedOn` is the computed property), the PDF per-EPA section via ReadForProfileAsync.
- **Migration.** Designer carries `[DbContext]` / `[Migration]` and differs from the previous Designer by exactly the new property; snapshot matches; column is nullable `jsonb`; Down drops it. SQL names are quoted and match the snapshot (`TraineeProfiles`, `CurriculumItems`, `Epas`, `IsActive`, `DeactivatedOn` timestamptz, `CompletedOn` date). `MinimumLevelByStageJson` is `text`, so `jsonb_build_object` embeds a JSON string, as `Parse` expects; enums are integers; keys are the camelCase names Parse reads; nulls become JSON null; no items gives `[]` as `Serialize` does; strict `>` equals `moment <`; `(date+1)::timestamp - 2h AT TIME ZONE 'UTC'` equals `EndOf`. Idempotence is by the column being new; profiles with no recorded end day stay null and read live (documented).
- **jsonb discipline.** Never compared as raw text; always `Parse`d.
- **Authorization.** No new read skips scope: changed readers take the profile the caller already resolved through `TraineeScopeResolver.PreferredProfiles` under the unchanged handlers' checks; `ProgrammeItems.ReadAsync` reads EPA code, title and IsActive by id only for items already on the trainee's own frozen list.
