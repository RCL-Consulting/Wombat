bd

Several roles, and switching

  • One acting role, shown on every page in the top bar: "Acting as · Committee member". One-role people see a plain label, not a button.
  • The button opens a native disclosure: the current role, then "Switch to Assessor". Switching opens that role's Home, so the map and the landing change together.
  • A link into the other role's page (an emailed rating request) switches the role and says so, as in A.
  • Remembered for the session, cleared at sign-out (T317); next sign-in lands by precedence.
c

Top bar

  • 56 px, sticky: the mark and Wombat (a link to Home, the only way back besides the first breadcrumb); then the role; the name (link to My Account); one Sign out.
  • A role label that wraps: the role button holds two lines up to 220 px wide; it never truncates.
  • A long name truncates at 24 characters; whole in its accessible name and title.
f

States

  • Failure pages sit under the top bar with one breadcrumb, "Home", and no "Also in" line.
  • Nothing to light: the breadcrumb's last item carries aria-current="page". That is how C meets T331.
  • The error bar spans the window's foot; the reconnect dialog is modal. Same as A and B.
g

The phone

  • Home is already a list, so the navigation needs no folding. The bar's CSS-only toggle ("Account") folds the role, the name and Sign out.
  • Breadcrumbs wrap; "Also in" wraps below the h1.
  • The same shell for static pages: only the account toggle, CSS-only.

Edge cases

  • Long navs: none; the Administrator's 17 pages are a directory on Home that fits one 800 px screen with its two waiting cards.
  • Deep links: a page reached from an email has breadcrumbs, so the way back is always visible.
  • Wide tables get the full width on every page.
  • The Home directory must stay a nav landmark ("Your pages") so screen reader users find it as navigation.
