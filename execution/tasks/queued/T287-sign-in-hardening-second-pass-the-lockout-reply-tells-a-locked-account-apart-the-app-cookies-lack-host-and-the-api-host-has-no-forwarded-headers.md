# T287 — Sign-in hardening, second pass: the lockout reply tells a locked account apart, the app cookies lack __Host-, and the API host has no forwarded headers

> **Compatibility is not a constraint** ([W-007]; CLAUDE.md § "Nothing is live"). There are no real users and no real
> data anywhere: dev and production hold scenario rows only. Do not design around existing rows, stored versions, pinned
> activities or old behaviour. Prefer the correct end state: re-author seeds, write destructive migrations, empty and
> re-seed a database. The scenario corpus is still the test corpus, so show the change working end to end.

**Severity:** Low.
**Surfaced:** 2026-09-25, the T156 review.

## Symptom and what to build

- **The lockout reply.** "Too many failed sign-in attempts…" answers on the first try for an account an admin
  deactivated, and after 5 guesses for an active local account, but never for an unknown or SSO-only address. Decide
  whether a locked-out person is told. **Recommendation:** the same generic refusal for all, with the lockout explained
  by email to the account's own address.
- **Cookies.** The application and antiforgery cookies could take the `__Host-` prefix, as the external cookie now does.
- **Timing.** Refusing a real local account takes longer (its password is hashed) than refusing an unknown address.
  Hash a dummy password for unknown addresses.
- **An Identity description.** A failed `AddLoginAsync` in `LinkAndSignInAsync` still shows Identity's text. Only a race
  can cause it.
- **The API host** has no forwarded-headers setup, so behind Caddy its MSF limits count Caddy as the client.
- **VerifyExport's placeholder** says "Enter the hash from the PDF footer", but the footer prints no hash. Reword it, or
  print the hash.

## Notes

- **T295 replay, 2026-09-26 (C42).** T295 replay, 2026-09-26, Step 5.13 (F-5.13b). A signed-out verifier saw the placeholder 'Enter the hash from the PDF footer' (design/baseline/states/verify-export--blank.png) while the 11-page PDF's footer read only 'Page n of 11 | Generated by Wombat'. This does not widen the item, but it settles the choice between its two options: reword. The stored hash is the SHA-256 of the whole file (PortfolioPdfService.cs:72), and a file cannot print its own hash, because printing it changes the bytes it hashes. So the placeholder should tell the verifier to compute the file's SHA-256 (sha256sum, certutil -hashfile <file> SHA256, or PowerShell's Get-FileHash). The new verify task from the same replay (case-insensitive match, deterministic answer, no 90-day cleanup) edits the same page and accepts Get-FileHash's upper case. Take this item with it if that task lands first.
- **T295 replay, 2026-09-26 (C50).** Notes, 2026-09-26 (the T295 replay, Steps A.4.4 and A.6.5; re-observed at A.7.12):
- **The lockout reply, and the page it points to.** At A.6.5 an administrator's lock answered `?error=LockedOut` with "Too many failed sign-in attempts. Please try again later or reset your password." (`SignInOutcome.LockedOutMessage`, SignInOutcome.cs:68; `design/baseline/states/login--locked-out.png`, `act-A/A.6.5-2-locked-out.png`). So a man locked out by his head of department is told he failed his sign-ins. Its first remedy does not work: the register page refuses an invitation to an address an account already holds ("A user with this email address already exists.", T285), and issuing an invitation does not check the address first (T286's note). **This widens the lockout item.** Reword both halves together, in words written for the user, and never point at a self-service reset while none exists. The lockout sentence follows the recommendation above. The forgot-password page says to ask the programme's administrator to reset the password, with no "rewrite" and no "new invitation". `PasswordResetEmail` (Application/Common/Email/Templates) has no caller: record whether self-service reset will be built, or delete the template. Verification: bUnit on the two sentences, and runbook Steps A.4.4 and A.6.5 re-played with their Expects changed to the new words (F-A.4.4a, F-A.6.5a).
