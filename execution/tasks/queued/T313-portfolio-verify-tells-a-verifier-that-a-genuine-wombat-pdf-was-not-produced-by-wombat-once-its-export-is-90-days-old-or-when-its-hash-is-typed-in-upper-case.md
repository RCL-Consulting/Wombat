# T313 — /portfolio/verify tells a verifier that a genuine Wombat PDF was not produced by Wombat once its export is 90 days old, or when its hash is typed in upper case

> **Compatibility is not a constraint** ([W-007]; CLAUDE.md § "Nothing is live"). There are no real users and no real
> data anywhere: dev and production hold scenario rows only. Do not design around existing rows, stored versions, pinned
> activities or old behaviour. Prefer the correct end state: re-author seeds, write destructive migrations, empty and
> re-seed a database. The scenario corpus is still the test corpus, so show the change working end to end.

**Severity:** Medium. The page exists to confirm a genuine PDF. Both defects make it say the opposite about a genuine graduate's portfolio: 'This hash does not correspond to any PDF generated by this system'. A credentialing officer would read that as a forgery.
**Surfaced:** 2026-09-26, the T295 replay of the rewritten scenario runbook (findings F-5.13a, F-A.2.9a).

## Symptom

- **Upper case (Step 5.13).** Signed out, the genuine PDF's SHA-256 typed in upper case, as PowerShell's Get-FileHash prints it (68A17034…EC9C), reads 'No matching export found. This hash does not correspond to any PDF generated by this system.' (design/baseline/act-5/5.13-2-verifier-uppercase-hash.png). The same hash in lower case reads 'Export verified' (5.13-1-verifier-genuine-verified.png).
- **Several exports (Step 5.13).** Three exports produced the same file (Steps 5.9, 5.10 and 5.12; T078 makes identical exports the normal case). The page shows one of them, chosen by no rule, so 'Exported by' and the generated time are whichever row PostgreSQL returns first. The replay got Dr Molefe's 12:09 export for Mr Smit's copy.
- **After 90 days (Appendix Step A.2.9).** portfolio-export-cleanup ('Deletes portfolio export records older than 90 days', daily at 02:00 UTC) deletes the rows the verify page reads, so 91 days after export the genuine file reads 'No matching export found'. This cannot be seen in replay time (the run logged 'no expired exports found.'); it is confirmed from the code.

## Root cause

- VerifyExport.cs:26-30 calls FirstOrDefaultAsync(record => record.ContentHash == request.ContentHash): an exact, case-sensitive comparison with no OrderBy. The stored hash is lower case (PortfolioPdfService.cs:72, Convert.ToHexStringLower), and the page sends Hash.Trim() unchanged (VerifyExport.razor:103).
- PortfolioExportCleanupJob.cs:27-40 removes every PortfolioExport row older than 90 days. It is registered at DependencyInjection.cs:154.
- T024 specified this job to delete expired export *files* under /opt/wombat/data/exports/: T023 step 7's background-generated PDFs with 24-hour links. Those were never built. The PDF is streamed to the browser and nothing writes to that folder, so the job's only effect is to delete the verification records.
- A PortfolioExport row holds no PDF, only the hash, two user ids, the filter and the file name. Erasure already pseudonymises it (ErasureExecutor.cs:295-303).

## What to build

- **Match a hex digest case-insensitively.** The query trims and lower-cases the submitted hash before the lookup.
- **Say when the value is not a hash.** A value that is not 64 hexadecimal digits gets its own message, not 'No matching export found'. For example: 'A SHA-256 hash is 64 hexadecimal characters; the file name carries only the first 12.'
- **Answer deterministically when several exports share the hash.** Show the first export (ORDER BY ExportedOn, Id) and say that the PDF was first generated then, how many times it has been exported, and when it was last exported. Ids stay ids, since DESIGN says the anonymous page must not disclose a name.
- **Keep verification records.** Remove PortfolioExportCleanupJob, its registration, its test and its ScheduledJobDefinition row (by migration, or the job registry's own sync). A PortfolioExport row lives as long as the trainee's record, and erasure's pseudonymisation stays the only change made to it. If a retention bound is wanted later, it must keep the hash row.
- **T287's placeholder item** ('Enter the hash from the PDF footer') is on the same page. Take it here if this task lands first.
